- **A task's own grader** (KAN-192, [docs/jobs/experiments.md](docs/jobs/experiments.md#grading)). An experiment task
  may carry `grader`, which replaces the experiment's for that task's trials and its base check: its own command and
  its own 64 files and 1 MB, with 16 MB across the experiment. With no experiment grader, every task needs one. One
  canary covers every grader. A task's own grader is part of its trial-cache identity and is pinned on its task in a
  pin set (`tasks.<id>.grader_digest`); `POST /api/trials` runs a task's own grader only when its pin set pinned it.
  Tasks without one keep their digests and pin set ids.
- **A task's own files** (KAN-192, [docs/jobs/experiments.md](docs/jobs/experiments.md)). An experiment task may carry
  `workspace`, its files in place of a repo (500 files, 1 MB; 16 MB across the tasks). hangar commits them, so the
  same files always give the same commit, keeps the commit as a bundle under the data directory and pins it as the
  task's base (`pins.tasks.<id>.workspace`). Each trial and grader sandbox clones it with no remote, so isolation and
  grading work as for a repo. The files are part of the task's trial-cache identity; tasks without them keep their
  digests. `POST /api/trials` runs a workspace task only when its files make the commit its pin set pinned.
