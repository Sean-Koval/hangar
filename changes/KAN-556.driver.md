- **Only the driver speaks for hangar in a run log** (KAN-556). The harness's stderr now reaches the log a whole line
  at a time, and a line hangar would read as one of the driver's `hangar.*` events is kept with a prefix, on stderr
  as on stdout. The test is the parser's own, so a line padded with a Unicode space, or nested deeper than the
  sandbox's Python parses, no longer slips through. The driver signs its events with the run's key: hangar reads no
  unsigned `hangar.*` line of a live run as an event, even when the key won't open, and a tree counts as trusted
  only with a valid signature. A harness that fills its stderr pipe no longer stalls a long prompt. A split run's
  log tail is read as hangar's user, not through the agent's container. A turn still running on the old driver
  when hangar upgrades loses its approval requests from the log; without the uid split they time out and are
  denied, so let live turns finish first. [How steering works](docs/steering/how-it-works.md#trees).
