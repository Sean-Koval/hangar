- **IAP sign-in needs allowed domains** (KAN-556). Breaking for IAP installs: `HANGAR_SSO_MODE=iap` now refuses to
  start without `HANGAR_SSO_ALLOWED_DOMAINS`, and serves Workspace accounts only, so an install behind IAP with
  consumer Google accounts or Identity Platform (no `hd`) can't use IAP mode. IAP's header doesn't say whether
  Google checked the email, so sign-in is held to a Workspace account (`hd`) of an allowed domain. Set the domains
  before upgrading. The console now checks the domain and the Google account (`sub`) on every request too, so a
  console session bound before the upgrade from outside those domains stops working. Its CLI and service tokens
  keep working until the binding's last check goes stale; review IAP bindings made before the upgrade.
  [Single sign-on with IAP](docs/security/sso-iap.md).
