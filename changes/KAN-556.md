- **The audit sink keeps only real audit lines** (KAN-556). `hangar serve` now writes each log record as one entry:
  every line after a record's first starts with `| `, uvicorn's lines, warnings and uncaught exceptions included,
  and a line over 16,000 bytes is cut into such lines before the container runtime splits it. The audit sink's
  filter in `deploy/terraform/gke/audit.tf` and `modules/hangar-workload/audit.tf`, and the read command they print,
  are anchored at the start of the line. A sandbox's output quoted in a warning can no longer put a line that looks
  like an audit record into the locked bucket. An audit record over 16,000 bytes now reaches the bucket cut short
  (its first piece only); the database keeps it whole. Run `terraform apply` to update the sink.
